# 出典規約 v0.1

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-08-26 |
| 対象 | リポジトリ内すべての文書の**技術的主張**——「〜できる」「〜すべき」「〜が推奨される」、性能・制約・料金・仕様に関する記述 |
| 目的 | AI と人間の双方が、主張の根拠を1クリックで原文の該当箇所まで辿れる状態を保つ（グラウンディング） |
| 根拠 | 先行調査 §8（research/2026-08-25_先行調査_AI駆動開発時代のドキュメント.md） |

## ルール

1. **技術的主張には一次情報の出典を付ける。** 出典のない技術的主張は「未検証」と見なす。
2. **本文を肥大化させない。** 本文には主張とリンク（または脚注マーカー）だけを書く。長い根拠は文書末尾の「根拠」節に次の3点セットで置く: (a) 原文の抜粋（**2文以内**。リンク切れ・原文変更への保険であって転載ではない）、(b) ディープリンク、(c) 参照日。
3. **ディープリンクは「節アンカー + text fragment」を重ねる。** URL 末尾に `#節アンカー:~:text=対象の文言` を付けると、開いた瞬間に該当文までスクロール・ハイライトされる（[Text fragments — MDN](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment/Text_fragments)）。日本語はパーセントエンコードで動く。文言が変わった場合はページ先頭が表示されるだけなので壊れても実害がない。
4. **出典を格付けする。** 一次（AWS 公式ドキュメント・公式ブログ・仕様書）＞ 二次（実績ある技術ブログ・書籍）＞ その他。**二次以下しか根拠がない主張には「⚠ 要一次確認」を付ける**——これは「一般的でない設計の可能性」のシグナルとして機能する。AWS 以外の技術は、その技術の公式ドキュメント・標準仕様（Web 標準なら MDN・W3C/WHATWG・IETF RFC）を一次とする。Wikipedia は概念の定義・命名の確認には使えるが、技術的主張の根拠としては「その他」扱い。
5. **実行で検証できる主張は IaC でも表現する。** 設計書の主張のうち CFn テンプレート断片で表現できるものはスニペットとして書き、cfn-lint / validate-template が通ることを確認する。「CFn で表現できない」こと自体が、実現できない設計の早期シグナルになる（先行調査 §8）。

## 記法例

```markdown
Lambda の同時実行数は、既定でアカウントあたり 1,000 に制限され、リージョン内の全関数で共有される[^1]。

## 根拠
[^1]: "By default, your account has a concurrency limit of 1,000 concurrent executions across all functions in a Region."
      https://docs.aws.amazon.com/lambda/latest/dg/lambda-concurrency.html#reserved-and-provisioned:~:text=your%20account%20has%20a%20concurrency%20limit%20of%201%2C000
      （参照日: 2026-08-26）
```

## enforcement（規約は機構が守らせる）

現状の機構: なし（この規約はまだ「願望」段階）。M3 周2 で citation-verifier subagent（出典を実際に開き主張と原文を敵対的に照合）+ 出典カバレッジチェックフックを導入して機構化する。それまでの暫定運用: 公開前に「技術的主張にリンクがあるか」をセルフチェックする。
