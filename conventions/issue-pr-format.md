# Issue / PR 書式規約（issue-pr-format）v0.1

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-08-26（作成過程規約 v0.4 から責務分離で切り出し） |
| 位置づけ | Issue と PR に何を書くかの規約。レビュー種別の語彙と反映コメントの書式を含む。作業の流れ自体は作成過程規約（conventions/authoring-process.md）が定める |

## Issue の必須欄

テンプレート: `.github/ISSUE_TEMPLATE/task.yml`（Issue Form 形式なので必須欄は空のまま作成できない）。

| 欄 | 内容 |
|---|---|
| 背景 | いまどういう状況・問題があるか（1〜3行） |
| 目的 | この Issue で何を実現したいか（1〜2行） |
| 達成条件 | 満たしたら完了と言える条件。チェックボックスで書く |
| 対応範囲 — やること | この Issue で扱う範囲 |
| 対応範囲 — やらないこと | 意図的な対象外と、その扱い先。**レビューの境界になる** |
| 依存 | 依存する Issue / PR。なければ「なし」 |

## PR の欄

テンプレート: `.github/pull_request_template.md`。

| 欄 | 内容 |
|---|---|
| 対応 Issue | `Closes #n` |
| 概要 | 読者が最初に知りたいことを1〜3行。**処理より先に結果・中身**。書き分けは下表 |
| 変更内容 | 主要な変更を**5点まで**。超える詳細は `<details>` に畳むかコミット履歴に任せる（squash 前の各コミットが意味単位の詳細リストになる）。5点で要約できないなら PR 分割を検討 |
| 対応範囲 | **Issue から増減があるときだけ**書く（一致していれば欄ごと省略）。書くときは最終的な範囲のみ。経緯・変更履歴は書かない（コミット履歴と反映コメントが持つ） |
| 確認したいこと | レビュー種別（下表）+ **質問文**の論点。レビュアーが「はい / いいえ / どちらか」で答えられる形に |

概要の書き分け（PR の種類ごとに、読者が最初に知りたいことは違う）:

| PR の種類 | 概要に書くこと |
|---|---|
| 仕組み・規約の変更 | マージ後に何がどうなるか（結果の姿） |
| 新しい文書の追加（設計書・research 等） | どんな文書か——何についての、どんな内容・判断を含む文書か |
| 修正（fix） | 何が・どう直るか |
| 実験の記録（exp） | 何を測り、何が分かったか（結論） |

PR 本文の原則: **レビュアーが読む欄だけ**で構成し、**PR 本文がレビュー依頼の正典**として常に最終状態を語る（canon.md の SSOT 原則の適用）。セルフチェックの実施や Agent チェックの結果は作者側の義務・記録であり、本文に申告欄を置かない。Agent チェックの合否は `agent-check:passed` ラベルと結果コメントで示す。

## レビュー種別（PR 作成者が「確認したいこと」で宣言する）

| 種別 | レビューで見ること | 見なくてよいこと |
|---|---|---|
| **内容** | 定義・判断・ルールに同意できるか。「これに従って運用する気になれるか」 | 文体・体裁・誤字 |
| **形式** | 規約への準拠（Agent チェックが未整備の項目のみ。機構ができた項目から人のレビュー対象外にする） | 内容の是非 |
| **FYI** | 軽微な修正・機械的な変更。異議がなければそのままマージ | — |

観点を絞る理由: 人間のレビュー容量は有限で、AI 駆動の生成速度に全量レビューは追いつかない（Comprehension Debt、先行調査 §5、research/2026-08-25_先行調査_AI駆動開発時代のドキュメント.md）。形式・整合の検査は作成・修正ループと Agent チェックに移し、人のレビューは内容の判断に集中させる。

## 反映コメントの書式

- 指摘ごとに見出しを立て、指摘の要約を見出しに書く
- 対応は**1行1項目の箇条書き**で書く。1項目は1文で完結させ、矢印（→）や括弧の連結で複数の内容を1文に詰め込まない
- 各指摘に該当コミット ID を添える
- 本文の更新が伴う場合は「本文を更新済み」と書く

## enforcement（規約は機構が守らせる）

- 導入済み: `.github/ISSUE_TEMPLATE/task.yml` + `config.yml`（必須欄が埋まらないと作成できず、blank issue も無効化。ただし欄を形だけ埋めた提出までは防げない）、`.github/pull_request_template.md`（レビュアー向けの欄のみ）、`agent-check:passed` ラベル
- 未導入（願望段階）: 達成条件・対応範囲のない Issue を検出する仕組み
